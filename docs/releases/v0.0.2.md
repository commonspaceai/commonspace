# Commonspace v0.0.2

Commonspace improves message delivery feedback, routing recovery, and visibility into native agent activity.

## Improvements

- See pending messages immediately while Commonspace admits them, with queue-aware delivery feedback.
- Inspect routing receipts and delivery status within conversations.
- Filter channel threads to find the conversations you need.
- See agent model information in the sidebar and native context compaction in agent activity.
- Refresh Hermes integration and its capability presentation.
- Find Projects by name as direct search destinations and open the exact matching reply.
- Retry a failed search without losing the query or filters, with announced search status.
- Navigate Workspace settings by keyboard with focus recovery and covered conversation controls removed from the keyboard path.
- Keep keyboard focus while reordering or removing queued follow-ups, and omit unavailable delivery actions.
- Apply Light/Dark/System appearance to native browser controls and preserve the selected mode across reloads.

## Fixes

- Recover failed routing decisions and keep classifier sessions isolated from conversation execution.
- Show newest harness activity first.
- Harden project-file, attachment, credential-file, and browser boundaries.
- Update compatible dependencies and improve Storybook and browser test reliability, preserving application and messaging coverage.
- Preserve edited inference settings after a failed save so the user can retry.
- Return to Inbox when a selected destination disappears during a workspace refresh.
- Keep previous search results unavailable when clearing filters starts another request.

Desktop interaction details are documented in [Using the desktop workspace](../guides/desktop-usage.md). Browser and Storybook checks establish the tested desktop flows; they do not establish clean-machine installation or provider-backed runtime compatibility. Expanded Gemini CLI and Pi support remain blocked on upstream native-session replay and MCP transport gaps, respectively; the [support matrix](../start/support.md) owns runtime evidence. Windows host installation and browser/service validation still require native Windows evidence. See the [release process](releasing.md) for candidate acceptance.
