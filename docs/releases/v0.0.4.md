# Commonspace v0.0.4

This patch prevents old Gemini replies from being appended to a new response after a session reload and improves release verification and recovery.

## Gemini session safety

- Reject Gemini session reloads after a server restart, process replacement, or changed MCP bindings. The supported Gemini runtime can replay history after reporting that a session has loaded, mixing old replies into new work.
- Preserve the exact saved session and accepted message when a reload is rejected. The message shows the failure and explains how to continue in Gemini CLI or use `/new` for fresh context.
- Continue using fresh Gemini sessions and sessions already loaded in the same process. Claude Code and OpenCode restart/resume behavior is unchanged.

## Release reliability

- Require successful main CI for the exact tagged commit before release verification and publication.
- Verify that npm serves the same tarball tested on Linux and Windows, including when recovering an already-published version.
- Preserve an existing published GitHub release during manual recovery. New releases use the reviewed release notes from the tagged commit.

## Installation and compatibility

```bash
npx --yes commonspace@0.0.4
```

The npm package requires Node.js 22 or newer. No saved-data migration is required. Gemini session reload remains unavailable until its native runtime can separate history replay from new replies. See the [support matrix](https://github.com/commonspaceai/commonspace/blob/v0.0.4/docs/start/support.md) for supported runtime boundaries.
